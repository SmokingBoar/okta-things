# Okta Event Type Glossary

Event types relevant to authentication analysis, including meaning, expected behavior, and investigation triggers.

---

## Authentication Events (High Signal — Always Analyze)

### `user.session.start`
New Okta session established.
- **SUCCESS** — Normal login.
- **FAILURE / INVALID_CREDENTIALS** — Wrong password. Legitimate after password reset (cached credentials). Suspicious if no preceding reset.

### `policy.evaluate_sign_on`
Okta evaluated a sign-on policy.
- **ALLOW** — Permitted. **CHALLENGE** — MFA required (policy working correctly). **DENY** — Blocked (investigate).
- **Key fields:** `target0.display_name` (policy), `target1.display_name` (rule name).

### `user.authentication.verify`
Identity verification during auth flow. Often appears in pairs/clusters — expected Okta Identity Engine behavior.

### `user.authentication.auth_via_mfa`
MFA challenge completed or attempted.
- **SUCCESS** — Passed. **FAILURE** — Failed. **ABANDONED** — Not completed (push dismissed/timed out).
- **Multiple ABANDONED in 5–15 minutes = high-priority signal for push-bombing investigation.** Cross-reference with `system.push.send_factor_verify_push`.

### `user.authentication.auth_via_AD_agent`
AD credential validation.
- **FAILURE "password has expired"** — Expected at rotation mark. Typically 1–2 times before reset.
- **FAILURE "INVALID_CREDENTIALS"** — Post-reset propagation lag or wrong password.
- **First appearance** in a user's logs is worth noting (new auth flow type).

### `user.authentication.sso`
SSO to downstream app. **Key:** `target0.display_name` = app name. Note first-appearance apps.

### `system.push.send_factor_verify_push`
Push sent to enrolled device. Multiple without corresponding MFA SUCCESS may indicate push-bombing.

## Device and Enrollment Events (Medium Signal)

### `system.email.new_device_notification.sent_message`
New device fingerprint detected. **High false positive rate** — Chrome auto-updates trigger this on the same machine. Investigate when combined with other anomalies.

### `user.mfa.factor.update`
**Almost always auto-generated by Okta Verify** — not user-initiated. Normal triggers: app version update, token renewal, network change, post-enrollment sync. 5–10 events in 30 minutes = normal.
**Ref:** https://support.okta.com/help/s/article/understanding-user-mfa-factor-update-events

### `user.mfa.factor.activate`
New MFA factor enrolled. Investigate if from unrecognized IP/device, especially after deactivation from different IP.

### `user.mfa.factor.deactivate`
MFA factor removed. Normal during phone upgrade. Investigate if from unrecognized IP.

### `system.agent.ad.reset_user_password` / `user.account.reset_password`
Password reset. Expected near rotation mark. Investigate if outside rotation window or from unrecognized IP.

## Admin Actions Against Accounts (Check Actor Field)

These appear in a user's log but are **admin actions, not user actions**. Always check `actor.alternate_id`. The device/IP belongs to the admin, not the subject.

- `user.lifecycle.suspend` / `unsuspend` / `deactivate`
- `user.session.clear` / `universal_logout`

**Never attribute these events to the subject user's device inventory.**

---

## Provisioning Events (Low Signal — Exclude from Auth Analysis)

- `app.user_management`, `application.user_membership.update`, `system.import.user.update`
- `app.realtimesync.import.details.update_user`
- `application.provision.user.push` / `.push_profile` / `.sync`
- `group.user_membership.add` / `.remove`
- `user.account.update_profile`

---

## Security Alert Events (High Signal — Always Investigate)

- `security.threat.detected` — Okta threat intelligence flag
- `user.account.lock` — Lockout from failed attempts
- `security.password_spray_attack` — P1-level indicator

## Outcome Reference

| Outcome | Meaning |
|---|---|
| `SUCCESS` | Completed |
| `FAILURE` | Failed — check `outcome.reason` |
| `ALLOW` | Policy permitted |
| `CHALLENGE` | MFA required — not a failure |
| `DENY` | Policy blocked |
| `ABANDONED` | Initiated but not completed |

---

## Key Fields

| Field | Description |
|---|---|
| `timestamp` | UTC. Convert to local time. |
| `actor.alternate_id` | User email. Primary filter. |
| `actor.type` | `User` or `SystemPrincipal` |
| `event_type` | Event type string |
| `outcome.result` | SUCCESS, FAILURE, ALLOW, CHALLENGE, DENY, ABANDONED, ERROR |
| `outcome.reason` | Explanation for non-SUCCESS |
| `client.ip_address` | Check against VPN ranges before flagging |
| `client.geographical_context.city` | May be VPN/proxy city |
| `client.user_agent.raw_user_agent` | Most important for device ID |
| `client.device` | `Computer` or `Mobile` |
| `authentication_context.external_session_id` | Groups events into sessions |
| `target0.display_name` | Policy name, app name |
| `target1.display_name` | Rule name, app instance |
